

| 特性              | `return HttpResponseNotFound(...)`                                           | `raise Http404(...)`                                            |
| ------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| **機制**          | **直接回傳**一個標準的 HTTP 回應物件。                                       | **拋出一個例外（Exception）** ，交由 Django 框架接手。          |
| **中斷執行**      | 不會自動中斷。如果後面還有程式碼，必須確保使用`return`才能停止視圖（View）。 | **立即中斷**當前視圖的執行，後續的程式碼絕對不會被執行。        |
| **自訂 404 頁面** | **不會**觸發全站統一的`404.html`範本。只會顯示你括號內寫的文字。             | **會**自動觸發並渲染 Django 全站設定的`404.html`範本。          |
| **使用情境**      | 適合用在 API 回傳簡單錯誤，或不需要漂亮外觀的臨時處理。                      | 適合用在標準網頁，確保使用者看到格式一致、美觀的 404 錯誤頁面。 |



詳細運作機制說明

1. return HttpResponseNotFound('找不到商品')

這是一個標準的函數回傳。你手動建立了一個狀態碼為 404 的回應物件，並將其送回給瀏覽器。
• 畫面呈現： 瀏覽器只會收到一個純文字「找不到商品」的空白畫面（或者是你包裝的 HTML 字串）。它不會讀取你專案中的 404.html 範本。
• 流程控制： 如果你在 View 的中途使用它，你必須加上 return。如果沒寫 return（例如只寫了 HttpResponseNotFound()），程式會繼續往下執行，可能導致非預期的錯誤。


2. raise Http404('找不到商品')

這是利用 Python 的例外機制（Exception）。你告訴 Django：「這裡發生了 404 錯誤，接下來交給你處理了！」
• 畫面呈現： Django 收到這個例外後，會自動去尋找專案中的 404.html 範本，並將其渲染給使用者。在開發模式下（DEBUG = True），Django 則會顯示一個詳細的除錯頁面，並把你寫的 '找不到商品' 顯示在畫面上，方便你除錯。
• 流程控制： 因為是 raise，程式一走到這行就會立刻中斷，後面的程式碼保證不會被執行，寫法上更安全、更直覺。
